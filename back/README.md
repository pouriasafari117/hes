# 💚  حسابت | سامانه مدیریت صندوق قرض‌الحسنه و موسسات بانکی

> یک سامانه مدرن، امن و یکپارچه برای مدیریت اعضا، حساب‌ها، وام‌ها، اقساط، تراکنش‌های مالی و گزارش‌های صندوق‌های قرض‌الحسنه.

---

## 📌 درباره پروژه

**حسابت** یک محصول نرم‌افزاری برای دیجیتالی‌کردن فرآیندهای مدیریتی و مالی صندوق‌های قرض‌الحسنه است.

هدف پروژه این است که مدیر یا حسابدار صندوق بتواند به‌جای استفاده از دفتر، فایل‌های Excel و فرآیندهای دستی، تمام اطلاعات صندوق را در یک محیط متمرکز مدیریت کند.

سیستم علاوه بر مدیریت اعضا و وام‌ها، می‌تواند وضعیت اقساط را به‌صورت خودکار بررسی کند و در صورت عبور از تاریخ سررسید، مورد معوق را به مدیر اطلاع دهد.

> 🎯 تمرکز اصلی محصول: **دقت مالی، کاهش کارهای تکراری، شفافیت، امنیت و تجربه کاربری ساده**

## 🔔 سیستم تشخیص اقساط معوق

یکی از قابلیت‌های کلیدی سیستم.

سیستم به‌صورت دوره‌ای وضعیت اقساط را بررسی می‌کند:

```text
اگر:
تاریخ امروز > تاریخ سررسید
و
مبلغ پرداخت‌شده < مبلغ قسط

آنگاه:
وضعیت قسط = OVERDUE
```

سپس در Dashboard مدیر نمایش داده می‌شود:

```text
🔴 ۷ قسط معوق

علی رضایی       ۱۲ روز تأخیر
محمد احمدی       ۸ روز تأخیر
حسین کریمی        ۵ روز تأخیر
```

این قابلیت می‌تواند در آینده با اعلان‌های داخل سیستم، پیامک یا ربات پیام‌رسان نیز توسعه پیدا کند.

## 📒 اتوماسیون حسابداری

یکی از اهداف توسعه محصول، تبدیل عملیات روزمره صندوق به رویدادهای مالی قابل ثبت و گزارش‌گیری است.

به‌جای اینکه کاربر مجبور باشد تمام ثبت‌های حسابداری را دستی انجام دهد:

```text
عملیات کاربر
      ↓
رویداد مالی
      ↓
ثبت حسابداری
      ↓
دفتر روزنامه
      ↓
دفتر کل
      ↓
گزارش مالی
```

### قابلیت‌های قابل توسعه

- دفتر روزنامه
- دفتر کل
- حساب‌ها
- سند حسابداری
- بدهکار / بستانکار
- تراز آزمایشی
- گزارش درآمد و هزینه
- گزارش دارایی‌ها و بدهی‌ها
- گردش حساب
- گزارش وضعیت وام‌ها

> ⚠️ پیاده‌سازی حسابداری رسمی و گزارش‌های قانونی باید مطابق استانداردها و قوانین حوزه فعالیت محصول بررسی و اعتبارسنجی شود.

## 🔐 امنیت

به دلیل ماهیت مالی سیستم، امنیت یکی از اولویت‌های اصلی پروژه است.

### اصول امنیتی

- Authentication امن
- Role-Based Access Control
- Permission Management
- ثبت Audit Log
- محافظت از اطلاعات حساس
- رمزنگاری ارتباطات با HTTPS
- مدیریت امن Session / Token
- اعتبارسنجی ورودی‌ها
- جلوگیری از دسترسی غیرمجاز
- Backup منظم
- ثبت رویدادهای حساس

### اصل مهم در تراکنش‌های مالی

اطلاعات مالی نباید بدون ردپا حذف شوند.

به‌جای:

```text
DELETE TRANSACTION
```

ترجیحاً از مفهوم:

```text
REVERSE / CANCEL TRANSACTION
```

استفاده شود تا سابقه عملیات حفظ شود.


### PRD
توضیح می‌دهد محصول **برای چه کسی، چه مشکلی را و با چه هدفی حل می‌کند.**

### PSD
رفتار دقیق سیستم، نیازمندی‌ها، قوانین کسب‌وکار، سناریوها، Edge Caseها و جزئیات اجرای قابلیت‌ها را مشخص می‌کند.

### ERD
ساختار داده و ارتباط بین موجودیت‌های دیتابیس را مشخص می‌کند.

### API
قرارداد ارتباط Frontend و Backend.

### ACCOUNTING
منطق حسابداری، حساب‌ها، بدهکار/بستانکار، اسناد و گزارش‌های مالی.

### SECURITY
نیازمندی‌ها و سیاست‌های امنیتی سیستم.
